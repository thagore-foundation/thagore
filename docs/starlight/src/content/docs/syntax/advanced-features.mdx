# Advanced Features

This page covers Thagore's advanced language features that go beyond basic syntax.

## Enums

Define algebraic data types with `enum`:

```python title="enums.tg"
enum Color:
    Red
    Green
    Blue

enum Shape:
    Circle(f32)
    Rectangle(f32, f32)
```

Enums with payloads (data attached to variants) are tracked by the compiler's feature counter system.

## Match Expressions

Pattern match on enum variants:

```python title="match.tg"
enum Direction:
    North
    South
    East
    West

func describe(d: Direction) -> String:
    match d:
        North:
            return "going up"
        South:
            return "going down"
        East:
            return "going right"
        West:
            return "going left"
```

<Aside type="note" title="Match + Enum Requirement">
The compiler validates that `match` is only used with at least one enum declaration in scope. A `match` without enums triggers error `E_TYPE_MATCH_MISSING_ENUM`.
</Aside>

## Type Aliases

Create type aliases with the `type` keyword:

```python title="type_alias.tg"
type Distance = f32
type Name = String
```

## Traits and `impl for`

Define interfaces with `trait` and implement them:

```python title="traits.tg"
trait Printable:
    func display(self) -> String

struct Point:
    x: i32
    y: i32

impl Printable for Point:
    func display(self) -> String:
        return "Point"
```

<Aside type="caution" title="Trait Status">
Trait declarations and `impl for` blocks are parsed and tracked by the compiler's feature counter (`extension_impl_count`), but full trait-based dispatch is still being implemented in the lowering pipeline.
</Aside>

## Visibility: `pub`

Mark declarations as public with `pub`:

```python title="visibility.tg"
pub func api_function() -> i32:
    return 42

pub struct PublicConfig:
    name: String
```

## `unsafe` Blocks

Mark code that requires unsafe operations:

```python title="unsafe.tg"
unsafe:
    let raw = malloc(1024)
    # raw pointer operations
    free(raw)
```

## `defer`

Schedule cleanup code that runs when the function exits:

```python title="defer.tg"
func process_file() -> i32:
    let handle = fs.open_read("data.txt")
    defer fs.close(handle)
    # ... process the file ...
    return 0
    # fs.close(handle) runs here automatically
```

<Aside type="caution" title="Function Scope Only">
`defer` is only valid inside function bodies. Top-level `defer` is rejected by the validation pipeline.
</Aside>

## `comptime` — Compile-Time Evaluation

Execute code at compile time:

```python title="comptime.tg"
comptime:
    let size = 4 * 1024
    # compile-time evaluated
```

The compiler tracks `comptime` blocks and evaluates them during the lowering phase via `lowering/transform/comptime/eval.tg`.

## Intent System

Thagore's unique **intent system** allows declarative, constraint-based programming:

```python title="intent_demo.tg"
intent func fib(n: i32) -> i32:
    goal: auto_plan
    constraints:
        deterministic == true

func fib(n: i32) -> i32:
    if (n < 2):
        return n
    return fib(n - 1) + fib(n - 2)

func main() -> i32:
    print(fib(35))
    return 0
```

### Intent Block Structure

```
intent func <name>(<params>) -> <type>:
    goal: <goal_name>
    strategy: <strategy> (optional)
    examples:
        <assertion expressions>
    constraints:
        <constraint expressions>
```

### Supported Goals

| Goal | Description |
|------|-------------|
| `auto_plan` | Compiler automatically selects an optimization strategy |
| `reduce_sum` | Optimize for sum reduction patterns |
| `off` | Disable intent optimization for this function |

### Intent with Examples and Constraints

```python title="intent_full.tg"
intent loop i in 0..10:
    goal: reduce_sum
    examples:
        reduce_sum([1,2,3]) == 6
    constraints:
        deterministic == true
        time <= O(n)
```

<Aside type="tip" title="Intent Validation">
The compiler validates intent goals through the `semantics/intent/matcher.tg` module. Unsupported goals trigger error `E_TYPE_INTENT_GOAL`.
</Aside>
