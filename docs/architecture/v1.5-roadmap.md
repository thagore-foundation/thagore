# Thagore Roadmap: v0.5 -> v1.5

## Product Goal

Deliver a platform for concurrency-safe native apps/services with low latency, no GC pauses, and no lifetime annotations required by end users.

Current baseline: `v0.5`.
Target milestone: `v1.5`.

## Strategic Themes

1. Structured concurrency by default.
2. Simple memory model (`Rc`/`Arc` + automatic `Send`/`Sync` checks).
3. High-quality async IO stack (minimal but production-ready).
4. Strong deployment story (single binary, fast startup, small footprint, one-command cross-compile).

## Version Roadmap

### v0.6 - Concurrency Primitives (Alpha)

Focus:

- Runtime task scope foundation.
- Nursery prototype.
- Parent-child cancellation propagation.

Deliverables:

- `runtime/`: task scope + nursery core APIs.
- `contracts/`: base behavior contracts for scope exit and cancellation.
- `tests/`: unit tests for task lifecycle invariants.

Gate:

- Child tasks cannot silently leak outside scope in test suite.

### v0.7 - Structured Concurrency by Default (Beta)

Focus:

- Timeout API and propagation semantics.
- Scheduler fairness and starvation protection.
- First deadlock/race regression lane.

Deliverables:

- `runtime/`: cancel + timeout + scheduler fairness hooks.
- `tests/integration/`: deadlock/race-oriented integration tests.
- `docs/runbooks/`: concurrency debugging playbook.

Gate:

- Scope/cancel/timeout behavior deterministic under stress tests.

### v0.8 - Memory Model MVP

Focus:

- `Rc` fast path for single-thread ownership sharing.
- `Arc` path for cross-thread sharing.
- Compiler checks for thread-safety boundaries.

Deliverables:

- `compiler/frontend` + `compiler/middleend`: automatic `Send`/`Sync` validations.
- `compiler/shared`: diagnostics with fix hints for `Rc` vs `Arc` misuse.
- `contracts/`: compile-time memory model compliance cases.

Gate:

- Invalid cross-thread `Rc` usage rejected at compile time with actionable diagnostics.

### v0.9 - IO Stack Alpha

Focus:

- Async runtime stabilization.
- Standard HTTP/WebSocket/DB clients (one recommended path each).
- Cancellation and timeout propagation through IO boundaries.

Deliverables:

- `runtime/`: async scheduler/backpressure improvements.
- `stdlib/` + adapters: HTTP/WebSocket/DB client interfaces.
- `tests/e2e/`: service-to-service async cancellation/timeout contracts.

Gate:

- End-to-end async IO path passes Linux parity contracts.

### v1.0 - Deploy Baseline

Focus:

- Single-binary default deployment.
- One-command cross-compile for primary targets.
- Cold-start and binary-size baselines in CI.

Deliverables:

- `compiler/backend`: codegen/link defaults for deploy ergonomics.
- `compiler/driver`: `thagc target` + `thagc build` one-command recipes.
- `tooling/`: CI budgets for startup + footprint.

Gate:

- One documented command can cross-compile per supported target family.

## Definition of Done by Theme

### 1) Structured Concurrency

- Task scope, nursery, cancel, timeout are default ergonomics.
- Orphan task/leaked task classes are blocked by design.
- Race/deadlock regression suite exists and runs in CI.

### 2) Memory Model

- `Rc` is the default single-thread shared owner.
- `Arc` is required and checked for cross-thread sharing.
- `Send`/`Sync` checks are automatic and enforced at compile time.

### 3) IO Stack

- Async runtime supports backpressure and cooperative cancellation.
- HTTP/WebSocket/DB standard clients are stable and documented.
- IO APIs stay minimal and opinionated (quality over quantity).

### 4) Deploy Story

- One binary artifact is default output for app delivery.
- Startup and footprint budgets are tracked in CI.
- Cross-compile to supported targets requires one documented command.

## Workstream Mapping to Repository

- `compiler/frontend` + `compiler/middleend`: semantic checks and memory model rules.
- `compiler/backend`: codegen/link changes for startup and footprint.
- `compiler/driver`: command UX for build/run/target/cross-compile.
- `runtime`: task scheduling, cancellation, timeout, nursery, IO runtime behavior.
- `contracts`: compatibility and parity behavior for concurrency/memory/IO/deploy.
- `tests`: unit/integration/e2e/soak/performance lanes.
- `tooling`: benchmark, policy, release automation, deterministic gates.
- `docs/runbooks`: release checklist, migration, incident response.

## Weekly KPIs

- Correctness: unit/integration/e2e/parity pass rate.
- Concurrency safety: deadlock/race regression count and MTTR.
- Latency: p50/p95/p99 on canonical service workloads.
- Deploy quality: startup time and binary size trendline.
- Portability: one-command cross-compile success rate by target.
