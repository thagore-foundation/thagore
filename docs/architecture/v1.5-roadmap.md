# Thagore v1.5 Roadmap

## Product Goal

Deliver a platform for concurrency-safe native apps/services with low latency, no GC pauses, and no lifetime annotations required by end users.

## Strategic Themes

1. Structured concurrency by default.
2. Simple memory model (`Rc`/`Arc` + automatic `Send`/`Sync` checks).
3. High-quality async IO stack (minimal but production-ready).
4. Strong deployment story (single binary, fast startup, small footprint, one-command cross-compile).

## Milestones

### v1.1 - Structured Concurrency Foundation

Scope:

- Add runtime-level task scope and nursery APIs in `runtime/`.
- Add cancellation propagation and timeout primitives.
- Introduce driver-facing execution contracts in `contracts/`.
- Add anti-deadlock and race-focused tests in `tests/integration/` and `tests/e2e/`.

Exit criteria:

- Child tasks cannot outlive parent scope by default.
- `cancel` and `timeout` semantics are deterministic under stress tests.
- No known deadlock scenario in baseline async examples.

### v1.2 - Memory Model Simplification

Scope:

- Define `Rc` as the default single-thread reference type (optimized hot path).
- Define `Arc` for cross-thread sharing.
- Add automatic `Send`/`Sync` validation in frontend + middleend checks.
- Add diagnostics in `compiler/shared/` with actionable error messages.

Exit criteria:

- `Rc` and `Arc` behavior is documented and contract-tested.
- Invalid cross-thread `Rc` usage is rejected at compile time.
- `Send`/`Sync` violations produce clear diagnostics with fix hints.

### v1.3 - IO Stack Quality Lane

Scope:

- Stabilize async runtime scheduler and backpressure behavior.
- Provide first-class HTTP, WebSocket, and DB client interfaces.
- Keep SDK surface minimal: one recommended client per capability.
- Add integration contracts for retry, timeout, and cancellation propagation.

Exit criteria:

- HTTP/WebSocket/DB clients pass parity contracts on Linux/macOS/Windows.
- End-to-end request path supports cancellation and timeout consistently.
- No required third-party wrappers for standard service-to-service IO.

### v1.4 - Deploy Story

Scope:

- Optimize static linking path for single-binary deployment.
- Improve startup path and cold boot codegen defaults.
- Add size/perf budget checks in CI.
- Implement one-command cross-compile flow via `thagc target` + `thagc build`.

Exit criteria:

- App deployment can use one binary artifact by default.
- Startup and memory footprint stay within predefined CI budgets.
- Cross-compile works with one documented command per target.

### v1.5 - Hardening and GA Gate

Scope:

- Concurrency model hardening (stress, soak, fuzz-inspired task interleavings).
- Runtime and compiler diagnostics polish for production incidents.
- Full release checklist and migration guidance.
- Final parity pass against contracts and deterministic gates.

Exit criteria:

- Structured concurrency + memory model + IO stack + deploy flow all marked stable.
- Soak and 3-OS matrix gates are green.
- v1.5 release notes and upgrade runbook are complete.

## Workstream Mapping to Repository

- `compiler/frontend` + `compiler/middleend`: `Send`/`Sync` checks, semantic rules.
- `compiler/backend`: codegen improvements for startup/footprint.
- `compiler/driver`: cross-compile UX (`build`, `target`, `run` command flows).
- `runtime`: task scope, nursery, cancel/timeout machinery, scheduler behavior.
- `contracts`: concurrency, memory, IO, and deploy behavior contracts.
- `tests`: unit/integration/e2e/soak lanes for release gates.
- `docs/runbooks`: release checklist, migration notes, benchmark reports.

## Release Gates to Track Weekly

- Correctness: unit/integration/e2e/parity pass rate.
- Concurrency safety: deadlock/race regression count.
- Latency: p50/p95/p99 for representative service workloads.
- Startup and footprint: cold-start time and binary size trend.
- Portability: one-command cross-compile success rate.
